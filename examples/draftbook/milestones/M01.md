# M01 — Save and resume a draft

Status: Draft — synthetic example.

Sources: [Product](../PRODUCT.md), [Roadmap](../ROADMAP.md).

## Outcome

The writer can save a local draft, close the application, and resume with the same title and text.

## Requirements and failure behavior

- Save the current title and body together.
- Reopening restores the latest successfully saved version.
- A save failure is visible and leaves the current editable text intact; do not imply it was saved.

## Acceptance examples and completion evidence

- Save title `Morning` and body `A short beginning.`, close, and reopen: both values are restored exactly.
- Edit the body and force storage failure: an error is shown and the edited text remains available for retry.
- Retry successfully and reopen: the new body is restored.
- Supply test or demonstration results for these cases. No implementation evidence currently exists.

## Non-goals and dependencies

No accounts, remote storage, sharing, multiple drafts, or version history. No predecessor milestone.

## Constraints and reasons

Keep draft content local to preserve the agreed first-release boundary.

## Suggestions and assumptions

Suggestion: reuse the repository's persistence abstraction if available. Assumption: suitable local storage exists; inspect the application to determine this. A missing library calls for technical investigation, not automatic creation of another milestone.

## Open decisions

None for this proposed example scope. A proposal to send drafts to a remote service changes the product/data boundary and must return to the owner.
